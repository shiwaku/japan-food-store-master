# 調査: fresh_food(青果・鮮魚・精肉店)を埋める別ソース

調査日: 2026-08-25(WebSearch・原典PDF・手元データ実測による)
背景: fresh_food はカバー率 29.7%(約10,070 / センサス582・583・584計 33,960)で、
チェーンスクレイピング(ATP方式)では個人商店が原理的に埋まらない(検証_AllThePlaces_網羅性と採用可否.md)。

## 最重要の発見: 農水省本家の2020年推計は「電話帳データ」を使っている

農林水産政策研究所レビュー No.122(髙橋克也「2020年食料品アクセスマップと困難人口の推計結果」、
[PDF](https://www.maff.go.jp/primaff/kanko/review/attach/pdf/241129_pr122_02.pdf))の原文:

> 2015年まで推計に用いていた『商業統計』が廃止されたため、2020年の推計では新たに
> **電話帳データ等の店舗の所在地がわかる情報**を用いている
>
> 店舗データ: 生鮮食料品販売店舗、食料品スーパー・コンビニ等 →2020年は
> 左記＋ドラッグストア(**日本スーパー名鑑、電話帳データ等**)

つまり公表値の生鮮レイヤーはタウンページ系電話帳データ製。「農水省推計の再現・突合」という
本リポジトリの用途では、電話帳系データは本家と同一系統のソースであり整合性の観点で別格。
ただし有償・再配布不可(後述)。

## 実測: 食品営業許可・届出データの生鮮3業種(新規集計)

`japan-facilities-address/api/facilities-all.csv`(1,437,799行)を全国集計:

| 業種(部分一致) | 行数 | 座標あり | 主な内訳 |
|---|---:|---:|---|
| 魚介類販売 | 39,369 | 36,663 (93.1%) | 許可(未包装)約30,700 / 届出(包装済のみ)約8,600 |
| 食肉販売 | 40,180 | 37,658 (93.7%) | 許可(未包装)約27,700 / 届出(包装済のみ)約12,400 |
| 野菜果物販売 | 15,516 | 14,939 (96.3%) | 全て届出(⑦野菜果物販売業 15,206 ほか) |
| **計** | **95,065** | **89,260** | |

- **青果店も載る**。「許可不要だから載らない」は誤りで、届出業種「⑦野菜果物販売業」に 15,516行。
  ただし届出は許可より捕捉が薄い(docs/permits のコンビニ半減と同じ構造リスク)。
- センサス3分類計 33,960 に対し約9.5万行=**不足ではなく過剰**。スーパーの鮮魚・精肉売場、
  市場内仲卸、卸兼業、移動販売が混入 → 課題は収集ではなく**フィルタリング**。
- docs/permits の「位置ソースに採らない」結論(台帳で複数行/コンビニ半分/県別不均質)は
  **届出業種を悉皆母集団として使う**評価であり、魚介・食肉は**許可業種**で捕捉が厚い。
  fresh_food 限定の gap-fill 用途なら矛盾しない。
- 弱点も既存docsの通り: 県別の穴(新潟・茨城・宮崎等)、座標 level 1(県代表点)混入
  → level≥3(できれば8+元座標)限定・`facilities-all_after.csv`(市名前置修正版)を使う。
  廃業行の混入可能性(現役判定が不完全)。

## 実施結果（2026-08-27 追記）

推奨順位1（許可・届出の fresh_food 限定・条件付き昇格）を実装して測った。
**効いた**: 純増 17,880件で3県の500m圏外率 62.2%→60.1%、比≤1 は維持、農水省公表値との相関 r は
0.448→0.460 に改善。前処理 (a)(b)(c)(d) は下記の通り実装・検証済みで、(a) の level 足切りだけは
level 1・2 の行がそもそも無く効いていない（代わりに level 3 の純増率が高いという別の論点が出た）。
→ [検証_許可データ_生鮮3業種_補完効果.md](検証_許可データ_生鮮3業種_補完効果.md)

## 推奨順位

1. **食品営業許可・届出の「fresh_food限定・条件付き昇格」**(無償・即着手可・再配布可=公開方針と両立する唯一の候補)。
   必須の前処理: (a) level≥3 に足切り、(b) 既存マスターと空間結合してテナント売場・重複を除外、
   (c) 許可(未包装)系を主とし包装済届出は原則除外、(d) 県別欠落はフラグ化。
   効果は必ず `validate_access_difficulty.py` のメッシュ検証器で測る(CLAUDE.md の原則)。
2. **ゼンリン企業サーチデータ or タウンページDB購入**(精度最優先・予算がある場合)。
   農水省と同一系統で突合整合性が最も高いが**再配布不可** → 公開マスターに混ぜられず、
   非公開の推計専用レイヤーとしてリポジトリ外分離が必須。まず見積で件数と価格の確認は価値あり。
3. 業界組合リストは 1 のフィルタ精度検証・地方の穴のクロス材料として補助的に。

不採用: Google Places(保存禁止)、iタウンページのスクレイピング(規約+判例)、
国土数値情報・商店街実態調査・公設市場名簿(店舗単位データが存在しない)。
